Vibe Coding vs Agent Engineering

探索我們與 AI 協作開發的演進過程，從單純依賴文字提示的直覺編程，走向能自主思考與操作工具的代理工程。

⏳ 時代發展與定義

Vibe Coding

約 2022 年底至 2024 年初

隨著 ChatGPT 等大型語言模型爆發而興起，帶有一點戲謔與直覺色彩的開發方式。

  • 運作模式： 開發者透過「自然語言對話」與 AI 互動，依靠反覆修改 Prompt 與 AI 的「直覺」來生成程式碼。像是將程式碼片段複製貼上到網頁聊天介面，告訴 AI「這個跑不動，幫我修」，然後把結果貼回 IDE 測試。
  • 核心技能： Prompt Engineering（提示詞工程）。

Agent Engineering

2024 年至今 (Agentic Workflow)

業界發現單純對話模型無法處理複雜專案，開始賦予 AI「工具」與「自主規劃能力」。

  • 運作模式： 開發者不再只是「要程式碼」，而是「設計與管理 AI 代理」。AI 被賦予系統權限（讀寫檔案、執行指令），能自主拆解任務、搜尋、撰寫、測試，並根據錯誤訊息自我修正。
  • 核心技能： 設定邊界與工具、建立工作流程（Workflow）、提供精確的 Context。

⚖️ 兩者的核心差異比較

比較維度 Vibe Coding (過去) Agent Engineering (現在與未來)
人類的角色 司機 / 搬運工 負責下指令、複製貼上程式碼、手動執行測試、把錯誤訊息貼回給 AI。 專案經理 (PM) / 審查者 (Reviewer) 負責定義高階需求、設定邊界條件、審查 Agent 的執行計畫與最終結果。
AI 的角色 高階自動完成器 只負責產出文字與程式碼建議。 虛擬工程師 (Virtual Engineer) 擁有感知（讀取檔案/終端機）與行動（修改檔案/執行指令）的能力。
上下文 (Context) 掌握 極度受限且被動 AI 只知道你手動貼給它的那幾行程式碼。 全面且主動 AI 可以主動使用搜尋工具（如 grep 或 ls）探索整個 codebase 的架構與關聯。
工作流程 (Workflow) 線性與中斷 人類提問 ➔ AI 回答 ➔ 人類測試 ➔ (失敗) ➔ 人類再提問。 自主迴圈 (Autonomous Loop) 人類下達目標 ➔ AI (思考 ➔ 尋找工具 ➔ 執行 ➔ 觀察結果) ➔ 自主修正直到成功。
除錯方式 (Debugging) 依賴開發者手動找出錯誤在哪裡，再把錯誤堆疊 (Stack Trace) 貼給 AI。 Agent 會自己下編譯或測試指令，自己看 Terminal 的紅字，然後自己去改 Code。
